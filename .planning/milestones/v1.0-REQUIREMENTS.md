# Requirements: Ohio Mutual Auto — Multi-Agent Claims Processing

**Defined:** 2026-02-17
**Core Value:** Every claims decision must be auditable, regulation-compliant, and defensible — demonstrating AI agents can process insurance claims with the rigor and accountability of human adjusters.

## v1 Requirements

Requirements for hackathon preparation deliverables. All code is written day-of; these requirements cover the knowledge artifacts, architecture designs, templates, and execution plans prepared in advance.

### Domain Research & Knowledge

- [ ] **DOMAIN-01**: Complete FNOL lifecycle documentation — what data is captured, how claims are categorized (collision/comprehensive/liability/theft/vandalism/weather), and why the sequence matters
- [ ] **DOMAIN-02**: Coverage verification knowledge base — policy lookup logic, exclusion types (intentional acts, racing, commercial use, excluded drivers, mechanical breakdown), deductible determination rules
- [ ] **DOMAIN-03**: Damage assessment methodology — labor + parts estimation approach, Ohio 100% ACV total loss threshold, OEM vs aftermarket parts decision framework (vehicles under 3yr/36K mi)
- [ ] **DOMAIN-04**: Fraud detection pattern catalog — minimum 5 named patterns (staged accident/swoop-and-squat, phantom passengers, paper accident, inflated repair, prior damage/VIN switching) with soft vs hard fraud distinction
- [ ] **DOMAIN-05**: Regulatory compliance reference — FCSP Act timelines (10-15 day acknowledgment, 40-day decision, 30-day payment), documentation retention requirements, bad faith exposure triggers
- [ ] **DOMAIN-06**: Payment and subrogation knowledge — deductible subtraction, depreciation (ACV vs RCV), subrogation logic (when insurer recovers from at-fault party), rental reimbursement rules
- [ ] **DOMAIN-07**: Edge case catalog — total loss handling, pre-existing damage detection, diminished value (17c formula), uninsured/underinsured motorist routing, claim reopening/supplements, weather surge/CAT events

### Architecture Design

- [ ] **ARCH-01**: OpenClaw configuration spec — complete `openclaw.json` with all 7 agents registered, unique agentDir paths, model assignments (Opus for reasoning agents, Sonnet for deterministic), maxSpawnDepth resolution, tool scoping per agent
- [ ] **ARCH-02**: Claim state JSON schema — full `claim.schema.json` defining all pipeline sections, audit_log format, status state machine (FNOL_RECEIVED → COVERAGE_CHECKED → ASSESSED → FRAUD_ANALYZED → REVIEWED → PAYMENT_ISSUED/DENIED)
- [ ] **ARCH-03**: Router/orchestrator design — sequential pipeline orchestration via sessions_spawn, announce-wait-read-spawn pattern, error handling, state machine transitions in AGENTS.md
- [ ] **ARCH-04**: Agent workspace structure — directory layout for all 7 agent workspaces with AGENTS.md templates (NOT SOUL.md — sub-agents don't receive it), tool scoping rationale per agent
- [ ] **ARCH-05**: Shared state architecture — filesystem-based JSON files for claim records, mock policy database (5 records: active, lapsed, excluded driver, high deductible, comprehensive-only), shared directory structure
- [ ] **ARCH-06**: Hand-off protocol specification — how each agent reads claim JSON, writes to its section, appends audit_log entry, announces completion; validation between stages
- [ ] **ARCH-07**: Human-in-the-loop escalation design — explicit triggers (fraud score threshold, claim value >$25K, total loss, legal representation, bad faith risk), escalation output format, pipeline pause mechanism

### Agent Specifications

- [ ] **AGENT-01**: Front Desk AGENTS.md template — FNOL intake checklist, claim categorization rules as reasoning framework (not hardcoded rules), structured output format, CAT event tagging logic
- [ ] **AGENT-02**: Claims Officer AGENTS.md template — coverage verification reasoning framework, policy lookup protocol, exclusion awareness, deductible determination, lapsed policy grace period, UM/UIM identification
- [ ] **AGENT-03**: Assessor AGENTS.md template — damage estimation methodology, Ohio 100% ACV total loss rule, OEM vs aftermarket recommendation framework, rental day calculation, pre-existing damage flag criteria, hidden damage likelihood
- [ ] **AGENT-04**: Fraud Analyst AGENTS.md template — named fraud pattern descriptions, soft vs hard fraud distinction, scoring rubric as reasoning framework (not numerical thresholds), SIU referral criteria, organized ring indicators
- [ ] **AGENT-05**: Senior Reviewer AGENTS.md template — decision framework (APPROVE/DENY/CONDITIONAL/ESCALATE_HUMAN), escalation trigger awareness, FCSP timeline compliance check, claim value threshold reasoning, diminished value awareness
- [ ] **AGENT-06**: Finance AGENTS.md template — payout calculation methodology (estimate minus deductible minus depreciation), subrogation flag logic, payment record format, supplement payment path, GAP insurance awareness
- [ ] **AGENT-07**: Router AGENTS.md template — state machine logic, sequential spawn pattern, task message enrichment (regulatory context injection), error handling, retry policy, pipeline control flow

### Deployment & Infrastructure

- [ ] **DEPLOY-01**: VPS setup script (`setup.sh`) — one-touch provisioning for Linux VPS (Ubuntu 22.04), OpenClaw gateway installation, Docker Compose configuration, environment variables, health checks
- [ ] **DEPLOY-02**: Demo scripts — `submit-claim.sh` (submit a test claim), `check-status.sh` (inspect claim state), `run-demo.sh` (full pipeline end-to-end execution from a single command)
- [ ] **DEPLOY-03**: Test claim scenarios — minimum 3 pre-built claim scenarios as JSON: happy path collision with subrogation, fraud rejection with SIU referral, coverage denial on exclusion

### Execution Playbook

- [ ] **EXEC-01**: Day-of timeline — hour-by-hour plan for 3 team members from arrival (9:00) through presentation (20:00), including secret addition integration window
- [ ] **EXEC-02**: Team work split — parallel workstream design (Member A: router + infrastructure, Member B: front-desk + claims-officer + policies, Member C: assessor + fraud-analyst), integration checkpoints at Hour 3 and Hour 5
- [ ] **EXEC-03**: Integration checkpoint protocol — what must work at each checkpoint, how to verify, rollback strategy if integration fails
- [ ] **EXEC-04**: Secret addition adaptation plan — framework for incorporating unknown requirement changes by editing AGENTS.md only (no code changes), covering three likely scenarios (new agent role, new regulation, claim surge)

### Presentation & Demo

- [ ] **DEMO-01**: 5-minute presentation script — narrative arc: problem (30s) → architecture (1min) → business logic (1.5min) → live demo (1.5min) → secret addition (30s)
- [ ] **DEMO-02**: Three demo claim walkthroughs — scripted narratives for: happy path collision ($4,200 damage, $500 deductible, subrogation flag), fraud rejection (phantom passengers, staged accident, SIU referral), coverage denial (commercial use exclusion)
- [ ] **DEMO-03**: Q&A defense document — prepared answers for anticipated questions covering business justification (why 6 agents, fraud handling, compliance), architecture decisions (tool scoping, state management, error handling), and regulatory knowledge (FCSP timelines, total loss threshold, bad faith)
- [ ] **DEMO-04**: Pre-run backup outputs — captured output from successful demo runs as fallback if live API fails during presentation

### Documentation

- [ ] **DOCS-01**: Architecture documentation with diagrams — pipeline flow, agent interactions, state transitions, tool scoping rationale
- [ ] **DOCS-02**: Agent documentation — each agent's purpose, tools, AGENTS.md content, decision-making approach, and why it exists in real insurance
- [ ] **DOCS-03**: Decision log — every architectural choice with rationale (database choice, model selection, tool scoping, orchestration pattern, why not SOUL.md)
- [ ] **DOCS-04**: OpenClaw tool/skill usage documentation — every OpenClaw primitive used (sessions_spawn, agent isolation, tool scoping, workspace structure), what it does, why we chose it, how it's configured

## Out of Scope

| Feature | Reason |
|---------|--------|
| Real payment processing / banking integration | Not possible in 10 hours, not needed for demo |
| Real photo AI / computer vision for damage estimation | Cannot build working ML model in 10 hours; claiming it risks credibility |
| Customer-facing portal / mobile app | Backend pipeline demo, not UX demo; judges score agent logic |
| Real policy database integration | Mock JSON records are sufficient and more transparent for demo |
| 50-state regulatory variations | Ohio-only; mention modular design for production in Q&A |
| SIU full simulation (field investigation, surveillance) | Real SIU involves humans; Fraud Analyst outputs referral document only |
| Hardcoded decision rules | Challenge explicitly says "thinking should not be hardcoded" — disqualifier |
| GAP insurance calculation | Too niche for demo value; mention awareness in Finance agent notes |
| Concurrent stress testing (100 claims) | Engineering theater; 3 sequential claims tell better business stories |
