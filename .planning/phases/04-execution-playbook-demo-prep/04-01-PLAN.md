Create docs/integration-checkpoints.md -- the protocol for integration checkpoints at Hour 3 and Hour 5.

**Checkpoint 1 (Hour 3 / ~13:00): Pipeline Skeleton**

What must work:
- Router can spawn Front Desk agent via sessions_spawn
- Front Desk processes a claim and writes to the correct pipeline section
- Router reads Front Desk output and validates required fields (completed_at, category, priority)
- If Member B has Claims Officer ready: Router spawns Claims Officer and it reads Front Desk output
- Shared directory structure exists: shared/state/claims/, shared/policies/, shared/schemas/

How to verify:
1. Submit happy-path-collision.json via submit-claim.sh
2. Check that Front Desk writes its pipeline section (check-status.sh)
3. Verify Router transitions status from FNOL_RECEIVED to INTAKE_COMPLETE
4. If Claims Officer ready: verify coverage check runs and covered=true

Pass criteria: Router successfully spawns at least Front Desk, and Front Desk output is valid JSON with all required fields populated.

Fail/rollback strategy:
- If Router cannot spawn: check openclaw.json agentDir paths, verify gateway is running, check agent ID matches
- If Front Desk fails: check AGENTS.md syntax, verify tool permissions (read + write), check claim file path
- If output validation fails: compare against claim.schema.json field requirements
- Rollback: revert to last known-good openclaw.json, re-deploy agent workspace

**Checkpoint 2 (Hour 5 / ~15:00): Full Pipeline**

What must work:
- Happy path claim runs through ALL 6 pipeline stages end-to-end
- Each stage writes its pipeline section correctly
- Router transitions through all statuses: FNOL_RECEIVED -> INTAKE_COMPLETE -> COVERAGE_CHECKED -> ASSESSED -> FRAUD_ANALYZED -> REVIEWED -> PAYMENT_ISSUED
- Audit log has entries from all 6 agents
- run-demo.sh completes without error for happy-path scenario

How to verify:
1. Run: `./scripts/run-demo.sh happy-path-collision`
2. Check final status is PAYMENT_ISSUED
3. Verify audit_log has 6+ entries (one per agent minimum)
4. Verify all pipeline sections have completed_at timestamps
5. Verify finance section has payment_amount_usd > 0 and subrogation_candidate = true

Pass criteria: Happy path claim reaches PAYMENT_ISSUED with complete audit trail.

Fail/rollback strategy:
- If any mid-pipeline agent fails: isolate which agent, check its AGENTS.md, test it individually via direct spawn
- If Router hangs: check timeout configuration, verify announce pattern in agent AGENTS.md
- Priority order for fixing: fix the failing agent first (most common), then check Router validation logic
- If time pressure: skip the failing agent in the pipeline temporarily (adjust Router AGENTS.md to skip that stage) and come back after other agents work

**General checkpoint rules:**
- Checkpoint takes max 30 minutes. If not resolved by then, flag it and move on with workaround.
- Member A (Router owner) leads checkpoint execution.
- All 3 members stop their work and participate in checkpoint.
- Document what worked and what did not in a shared scratchpad for demo preparation.
