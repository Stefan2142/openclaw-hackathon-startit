**Format:** Each section has a timestamp range and the actual words the presenter says (not bullet points -- actual sentences to speak). Include [ACTION] markers for when to switch slides, run commands, or point at the screen.

**Script structure:**

### Section 1: Problem Setup (0:00 - 0:30)
Hook the audience with the business problem: Auto insurance claims processing is broken. A single claim touches 6+ specialists, takes days to weeks, and every handoff is a point where compliance failures, fraud, and bad faith exposure creep in. Ohio's Fair Claims Settlement Practices Act requires acknowledgment in 10-15 days and decisions in 40 days -- miss those deadlines and the insurer faces regulatory action and bad faith lawsuits.

The presenter should frame this as: "What if you could process a claim through every specialist -- intake, coverage, damage assessment, fraud analysis, review, and payment -- in minutes instead of weeks, with a complete audit trail that proves regulatory compliance at every step?"

### Section 2: Architecture Overview (0:30 - 1:30)
Show the system architecture diagram (reference docs/ARCHITECTURE.md Section 1 ASCII art). Walk through:
- OpenClaw gateway receives claim submission
- Router agent (the orchestrator) reads the claim and spawns specialized agents sequentially
- 6 pipeline agents: Front Desk, Claims Officer, Assessor, Fraud Analyst, Senior Reviewer, Finance
- Each agent has scoped tools (least privilege), isolated workspace, and reasoning-framework instructions
- Shared claim JSON file is the state -- every agent reads it, writes to its section, appends to the audit log
- Key architectural decisions: JSON files (not database) for transparency, sequential pipeline for correctness, AGENTS.md reasoning frameworks for adaptability

Name-drop 3-4 OpenClaw primitives: sessions_spawn (agent orchestration), tool scoping (least privilege), agent isolation (workspace sandboxing), AGENTS.md (operating instructions)

### Section 3: Business Logic Deep Dive (1:30 - 3:00)
This is the differentiator section -- show the judges that the team understands insurance deeply.

Walk through what each agent actually knows:
- Front Desk: FNOL categorization (collision/comprehensive/liability/theft/vandalism/weather), CAT event detection, priority assignment
- Claims Officer: Policy lookup, exclusion checking (intentional acts, racing, commercial use, excluded drivers), deductible determination, UM/UIM routing, ambiguity doctrine (coverage ambiguity resolved in claimant's favor)
- Assessor: Labor + parts estimation, Ohio 100% ACV total loss rule, OEM vs aftermarket recommendation (vehicles under 3yr/36K mi), pre-existing damage flagging, hidden damage likelihood
- Fraud Analyst: 7 named patterns (staged accident, phantom passengers, paper accident, inflated repair, prior damage, friendly tow, VIN switching), soft vs hard fraud distinction, SIU referral criteria, indicator convergence scoring (not hardcoded thresholds)
- Senior Reviewer: Decision authority (APPROVE/DENY/CONDITIONAL/ESCALATE_HUMAN), FCSP timeline compliance check, escalation triggers (fraud score, claim value >$25K, total loss, legal representation, bad faith risk)
- Finance: Payout calculation (estimate - deductible - depreciation), subrogation identification, payment record generation

Emphasize: "None of these decisions are hardcoded if/then rules. Each agent uses reasoning frameworks -- principles and judgment guidelines that work like a real adjuster's training, not a decision tree."

### Section 4: Live Demo (3:00 - 4:30)
[ACTION] Switch to terminal

Use run-demo.sh for the happy path claim. While it runs, narrate what each agent is doing (reference happy path walkthrough from docs/demo-walkthroughs.md).

Key moments to highlight:
- Front Desk categorizes as collision, normal priority
- Claims Officer verifies coverage, finds $500 deductible
- Assessor estimates ~$4,200 in damage, flags subrogation potential
- Fraud Analyst finds low risk (legitimate claim)
- Senior Reviewer approves
- Finance calculates payment: $4,200 - $500 deductible = $3,700, flags subrogation against State Farm

Final moment: Show the audit log -- every decision, every agent, every reasoning step documented. "This is what regulators want to see. This is what protects the insurer from bad faith claims."

This is the power of reasoning-framework-based agents: new business requirements become new knowledge, not new engineering."

Close with: "Six agents. One pipeline. Complete audit trail. Regulatory compliance by design. That is Ohio Mutual Auto."
