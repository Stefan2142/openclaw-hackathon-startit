  <name>Task 1: Create hand-off protocol specification</name>
  <files>architecture/handoff-protocol.md</files>
  <action>
Create a detailed hand-off protocol document specifying every agent-to-agent transition.

**For each of the 6 transitions**, document:

**Transition 1: Router → Front Desk**
- What Router writes to claim JSON before spawning (initial claim record, status: FNOL_RECEIVED)
- What Front Desk reads (full claim JSON + incident data)
- What Front Desk writes (pipeline.front_desk section: category, priority, cat_event, missing_info)
- What Front Desk sets status to (COVERAGE_CHECKED... wait, no — Front Desk sets to trigger next stage)
- Announce format: SUCCESS + summary | ERROR + reason
- Router validation before spawning Claims Officer: front_desk.completed_at exists, category is set

**Transition 2: Front Desk → Claims Officer (via Router)**
- What Router passes in task message (claim path + policy path)
- What Claims Officer reads (claim JSON + policy JSON from shared/policies/)
- What Claims Officer writes (pipeline.claims_officer: covered, deductible, exclusions_checked, denial_reason)
- Status transition: FNOL_RECEIVED → COVERAGE_CHECKED
- Router validation: claims_officer.completed_at exists, covered is boolean

**Transition 3: Claims Officer → Assessor (via Router)**
- Skip if covered=false (Router sends to Senior Reviewer for denial documentation)
- What Assessor reads (claim JSON, photo references)
- What Assessor writes (repair_estimate, total_loss, parts_recommendation, etc.)
- Status: COVERAGE_CHECKED → ASSESSED

**Transition 4: Assessor → Fraud Analyst (via Router)**
- What Fraud Analyst reads (full claim JSON including all prior stages)
- What Fraud Analyst writes (risk_score, flags[], recommendation)
- Status: ASSESSED → FRAUD_ANALYZED

**Transition 5: Fraud Analyst → Senior Reviewer (via Router)**
- If recommendation=REFER_SIU → Router may set ESCALATED before Senior Reviewer
- What Senior Reviewer reads (full claim history, all prior decisions)
- What Senior Reviewer writes (decision, reasoning, escalation info)
- Status: FRAUD_ANALYZED → REVIEWED

**Transition 6: Senior Reviewer → Finance (via Router)**
- Only if decision=APPROVED or CONDITIONAL
- If DENIED or ESCALATE_HUMAN → pipeline stops, Router announces outcome
- What Finance reads (decision + damage estimate + deductible)
- What Finance writes (payment calculation, subrogation flag, payment reference)
- Status: REVIEWED → PAYMENT_ISSUED

**For each transition, include:**
- Pre-condition check (what the Router validates)
- Post-condition check (what the Router confirms after announce)
- Error path (what happens if announce is ERROR or ESCALATE)
- Audit log entry format for the transition

**Also document the announce message format** that all agents use:
```
Status: SUCCESS | ERROR | ESCALATE
Summary: [what was done]
Key findings: [important outputs]
Next recommended action: [what Router should do]
```

<task type="auto">
  <name>Task 2: Create human-in-the-loop escalation design</name>
  <files>architecture/human-in-the-loop.md</files>
  <action>
Create the human-in-the-loop escalation design document.

**1. Escalation Triggers (explicit catalog):**

| Trigger | Source Agent | Condition | Severity |
|---------|-------------|-----------|----------|
| High fraud risk | Fraud Analyst | risk_level = "critical" or recommendation = "REFER_SIU" | High |
| Large claim value | Assessor | repair_estimate > $25,000 | Medium |
| Total loss | Assessor | total_loss = true | Medium |
| Legal representation | Front Desk / Router | attorney letter received or legal_rep noted | High |
| Bad faith risk | Senior Reviewer | FCSP timeline approaching deadline | High |
| Coverage ambiguity | Claims Officer | covered = null (uncertain) | Medium |
| Prior fraud history | Fraud Analyst | claimant has prior fraud flags | Medium |

Frame triggers as reasoning principles, not hardcoded thresholds. Example: "Claims of significant value relative to typical claim patterns warrant additional human oversight" rather than "if > $25K then escalate."

**2. Escalation Output Format:**
```json
{
  "escalation": {
    "triggered_by": "fraud-analyst",
    "trigger_reason": "Multiple converging fraud indicators",
    "claim_id": "CLM-2026-00001",
    "severity": "high",
    "summary": "...",
    "recommended_action": "SIU investigation before proceeding",
    "pipeline_position": "after FRAUD_ANALYZED",
    "time_in_pipeline": "PT15M",
    "regulatory_deadline": "2026-03-25T00:00:00Z"
  }
}
```

**3. Pipeline Pause Mechanism:**
- Agent sets `senior_reviewer.escalated_to_human = true` in claim JSON
- Agent sets claim status to `ESCALATED`
- Agent announces `ESCALATE` to Router
- Router stops spawning further stages
- Router writes escalation to audit_log
- Claim sits in ESCALATED status until human resolution

**4. Human Resolution Path:**
- Human reviews escalation details in claim JSON
- Human sends resolution to Router session (approve / deny / modify)
- Router updates claim JSON with human decision
- Router resumes pipeline from escalation point (typically Senior Reviewer or Finance)
- Audit log records human intervention with timestamp

**5. Demo Implications:**
- For the hackathon demo, ESCALATED claims show the system's judgment about when to defer
- This is a competitive differentiator: shows responsible AI that knows its limits
- Prepare one demo scenario that triggers escalation (fraud rejection scenario)

**6. FCSP Timeline Compliance in Escalation:**
- Even escalated claims have regulatory deadlines
- Senior Reviewer checks elapsed time from FNOL
- If approaching 40-day decision deadline → urgency flag
- This prevents escalation from becoming regulatory non-compliance
