<task type="auto">
  <name>Task 2: Create demo runner scripts</name>
  <files>scripts/submit-claim.sh, scripts/check-status.sh, scripts/run-demo.sh</files>
  <action>
Create three demo scripts:

**Script 1: submit-claim.sh**
Submit a test claim to the pipeline.
```bash
#!/usr/bin/env bash
# Usage: ./submit-claim.sh [scenario-name]
# Scenarios: happy-path, fraud-flag, no-coverage
# Copies test claim to shared/state/claims/ and triggers router
```
- Accepts scenario name as argument (defaults to "happy-path")
- Generates unique claim ID: CLM-YYYY-NNNNN (timestamp-based)
- Copies from shared/test-claims/{scenario}.json to shared/state/claims/{CLAIM_ID}.json
- Updates claim_id and submitted_at in the new file using jq
- Sends trigger message to router via OpenClaw CLI or API: `openclaw chat --agent router "New claim submitted: {CLAIM_ID}"`
- Prints claim ID for tracking

**Script 2: check-status.sh**
Inspect claim state formatted for readability.
```bash
#!/usr/bin/env bash
# Usage: ./check-status.sh <CLAIM_ID>
# Shows claim status, current pipeline stage, key decisions
```
- Takes claim ID as argument
- Reads claim JSON from shared/state/claims/{CLAIM_ID}.json
- Uses jq to display:
  - Current status
  - Completed pipeline stages (where completed_at is not null)
  - Key decisions from each completed stage
  - Latest audit log entries (last 5)
- Color-coded output (green for completed stages, yellow for in-progress)

**Script 3: run-demo.sh**
Full end-to-end demo execution.
```bash
#!/usr/bin/env bash
# Usage: ./run-demo.sh [scenario]
# Runs complete pipeline for a demo scenario and displays results
```
- Accepts scenario (defaults to "happy-path")
- Calls submit-claim.sh to start the claim
- Polls check-status.sh every 5 seconds until status is terminal (PAYMENT_ISSUED, DENIED, ESCALATED, ERROR)
- Timeout after 5 minutes (safety)
- On completion: displays full claim summary using check-status.sh
- Optional: `--all` flag to run all 3 scenarios sequentially

All scripts should:
- Have proper shebangs and set -euo pipefail
- Print clear, demo-friendly output (not debug noise)
- Work from the project root directory
- Use $PROJECT_ROOT or relative paths consistently
