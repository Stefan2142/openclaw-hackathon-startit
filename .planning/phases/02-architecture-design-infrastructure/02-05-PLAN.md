<task type="auto">
  <name>Task 2: Create decision log and OpenClaw tool documentation</name>
  <files>docs/decision-log.md, docs/openclaw-tools.md</files>
  <action>
Create TWO documentation files:

**Document 1: decision-log.md**

Record every architectural decision with rationale. Format:

| # | Decision | Options Considered | Choice | Rationale |
|---|----------|-------------------|--------|-----------|

**Decisions to document:**

1. **Database: JSON files** — Options: Postgres, SQLite, JSON files. Choice: JSON files. Rationale: Zero setup, demo-readable, audit-friendly, native to OpenClaw filesystem tools.

2. **Model tiering: Opus for reasoning, Sonnet for deterministic** — Options: Opus everywhere, Sonnet everywhere, mixed. Choice: Mixed. Rationale: Cost optimization without quality sacrifice. Opus for Router/Assessor/Fraud/Reviewer, Sonnet for FrontDesk/ClaimsOfficer/Finance.

3. **maxSpawnDepth: 1** — Options: 1, 2. Choice: 1. Rationale: Router is depth-0 main agent, pipeline agents are depth-1 leaves. No nesting needed. Simpler configuration, fewer failure modes.

4. **AGENTS.md only (no SOUL.md for sub-agents)** — Options: SOUL.md + AGENTS.md, AGENTS.md only. Choice: AGENTS.md only. Rationale: Sub-agents only receive AGENTS.md + TOOLS.md. SOUL.md is invisible. All operating instructions must be in AGENTS.md.

5. **Sequential pipeline (not parallel)** — Options: Parallel stages, sequential. Choice: Sequential. Rationale: Correctness requirement — fraud analysis needs damage estimate, Senior Reviewer needs fraud score. Business logic mandates ordering.

6. **Reasoning frameworks (no hardcoded rules)** — Options: Rule tables, reasoning frameworks. Choice: Reasoning frameworks. Rationale: Challenge explicitly disqualifies hardcoded rules. LLM reasoning from principles is more adaptable (secret addition).

7. **agentToAgent disabled** — Options: Enable direct messaging, disable. Choice: Disabled. Rationale: All communication through claim JSON + Router mediation preserves audit trail and Router visibility.

8. **Tool scoping: least privilege** — Options: Full tools for all, least privilege. Choice: Least privilege. Rationale: Finance is only pipeline agent with exec. No pipeline agent can spawn. Demonstrates security awareness.

9. **VPS deployment: Docker Compose on Hetzner** — Options: Docker, direct install, cloud PaaS. Choice: Docker Compose. Rationale: Official documented path, reproducible, volume mounts for state persistence.

10. **Shared filesystem for state** — Options: API calls, message passing, shared files. Choice: Shared files. Rationale: Native to OpenClaw workspace model. Agents use read/write tools directly. Maximum demo legibility.

**Document 2: openclaw-tools.md**

Document every OpenClaw primitive used in the system:

1. **sessions_spawn** — What: spawn a sub-agent session. How used: Router spawns each pipeline agent. Config: agentId, task message, runTimeoutSeconds, cleanup policy. Why: Only documented orchestrator pattern for targeted sub-agent invocation.

2. **sessions_list** — What: list active sub-agent sessions. How used: Router checks pipeline status. Why: Enables Router to track which stages are running.

3. **sessions_history** — What: read sub-agent session transcript. How used: Router reads detailed output on errors. Why: Debug failed pipeline stages without rerunning.

4. **Agent isolation (agentDir)** — What: unique auth/session directory per agent. How used: Each agent has unique workspace path. Why: Prevents auth collisions between agents.

5. **Tool scoping (allow/deny)** — What: per-agent tool restrictions. How used: Pipeline agents get read/write only. Why: Least privilege prevents unauthorized actions.

6. **Workspace structure (AGENTS.md/TOOLS.md)** — What: injected files per session. How used: AGENTS.md contains all business logic. Why: Sub-agents only get AGENTS.md + TOOLS.md — this is the primary configuration surface.

7. **Bindings (default agent)** — What: route inbound messages to specific agent. How used: Router is default agent. Why: All claim triggers go to Router for orchestration.

8. **Model config (per-agent override)** — What: different LLM models per agent. How used: Opus for reasoning agents, Sonnet for deterministic. Why: Cost optimization without quality loss.

For each: what it does, why we chose it, how it's configured in our openclaw.json.
