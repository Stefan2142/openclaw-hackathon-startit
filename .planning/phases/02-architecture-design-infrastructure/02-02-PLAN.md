Create TWO architecture documents:

**Document 1: router-design.md — Router/Orchestrator Design**

1. **State Machine Logic:**
   - Complete state transition diagram: FNOL_RECEIVED → COVERAGE_CHECKED → ASSESSED → FRAUD_ANALYZED → REVIEWED → PAYMENT_ISSUED/DENIED
   - Plus error states: ESCALATED, ERROR
   - For each transition: what triggers it, what the router checks before spawning next stage

2. **Sequential Spawn Pattern (announce-wait-read-spawn):**
   - Step-by-step: router writes initial claim JSON → spawns front-desk → waits for announce → reads updated claim → validates stage output → spawns claims-officer → repeat
   - sessions_spawn call format with agentId, task message template, runTimeoutSeconds per stage
   - How the router constructs the task message: claim file path (absolute), regulatory context injection, what the agent should do

3. **Task Message Template:**
   ```
   Process auto insurance claim {CLAIM_ID}.

   Claim file: {ABSOLUTE_PATH}/shared/state/claims/{CLAIM_ID}.json
   {Additional context files if needed}

   Instructions:
   1. Read the claim file
   2. Verify prior stage ({PRIOR_STAGE}) is complete
   3. Perform your analysis per AGENTS.md
   4. Write results to pipeline.{YOUR_SECTION}
   5. Append audit_log entry with reasoning
   6. Update status to {NEXT_STATUS}
   ```

4. **Error Handling and Retry:**
   - Timeout handling: per-stage timeouts (front-desk: 60s, claims-officer: 90s, assessor: 120s, fraud-analyst: 90s, senior-reviewer: 90s, finance: 60s)
   - Retry policy: max 2 retries per stage, then ERROR status
   - Error announce parsing: Status line from announce → router action
   - Escalation triggers from each stage

5. **Context Enrichment:**
   - What regulatory context the router injects per stage (FCSP timelines, Ohio-specific rules)
   - How the router reads Phase 1 domain knowledge at startup

**Document: shared-state.md**

1. **Directory Structure:**
   ```
   shared/
   ├── schemas/
   │   └── claim.schema.json      (from 02-01)
   ├── state/
   │   └── claims/                 (runtime claim files, one per claim)
   ├── policies/                   (mock policy database)
   ├── uploads/                    (photo attachments per claim)
   └── test-claims/                (pre-built test scenarios — Phase 3)
   ```

2. **Path Convention:**
   - All agents use absolute paths: `/path/to/project/shared/state/claims/CLM-2026-00001.json`
   - Router constructs paths and passes in task messages
   - Agents never construct paths themselves

3. **Concurrency Model:**
   - Sequential pipeline: one writer per claim at a time
   - Multiple claims can process simultaneously (different files)
   - No file locking needed with sequential spawn pattern

4. **Mock Policy Database (5 records):**
